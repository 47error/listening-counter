# Listening Counter v2：資料與驗收

## 修改範圍

沿用原有 React、Vite、IndexedDB、白底鼠尾草綠 UI、Web Locks 寫入鎖（修復後僅在單次寫入持鎖）及 Last.fm Netlify Function。無新增後端、付費 API、登入要求或部署設定。

- `src/domain.ts`：v2 快照、驗證、v1 遷移、平台管理、分平台統計、手動批次、刪除去重鍵、歌曲合併及疑似重複提示。
- `src/db.ts`：在載入時驗證並升級快照；原始 IndexedDB 不清空、不刪除、不變更 object store。
- `src/main.tsx`、`src/PlatformTools.tsx`、`src/styles.css`：平台篩選、占比、歌曲平台明細、日期／批次計數、封存平台、合併、疑似重複與 JSON 匯入預覽／結果。
- `src/takeout.ts`：本機 Takeout JSON 候選解析與逐筆確認匯入。
- `tests/`、`playwright.config.ts`、CI、套件鎖：資料庫／領域測試及 Chromium 手機尺寸操作測試。

## 遷移與風險

IndexedDB 仍是 `listening-counter`，資料庫版本 1、object store `state`、key `main`。歌曲與事件仍以快照內獨立 `songs`／`plays` 陣列儲存，沒有重建專案或資料庫。

載入 v1 時先複製再驗證，在記憶體產生 `schemaVersion: 2`，待下一次成功操作才原子寫入完整快照。遷移可重複執行。歌曲 ID、事件 ID、時間、來源、外部鍵、帳號、同步游標／watermarks、分類及目標全部保留；不推定任何舊紀錄的平台（包括手動紀錄），全部設為 `unknown`（Last.fm／來源未確認）。舊版沒有建立時間，`createdAt` 使用原聆聽時間回填，並標記 `creationTimeInferred: true`，不代表已知的實際建立時間。

v2 新增 `platforms` 及 `ignoredKeys`。事件新增 `platformId`、`createdAt`、可選 `batchId`；來源為 `manual`、`lastfm` 或 `import`。新版備份包含這些欄位、全部歌曲與事件。舊版備份先驗證再遷移。備份還原改為預覽後「安全補入」，不取代現有資料，衝突整批停止，重複還原不累加；不保留備份游標，以原始外部鍵重查去重。還原前應先下載目前備份。

資料格式異常、孤立事件、重複 ID／外部鍵、不存在的平台、錯誤時間等會拒絕載入或還原，不嘗試清除或修復原始資料。若原始資料已損壞，需個別調查。

回滾舊程式無法理解 v2；先在新版匯出備份並保留升級前的 v1 備份。不可將 v2 備份交給舊程式覆寫。瀏覽器容量不足時交易失敗會回報錯誤；大量事件仍受原有完整快照架構及裝置記憶體限制。

## 去重與合併

- Last.fm 保留原鍵：來源＋正規化帳號＋時間＋歌手／歌名／專輯。重查 48 小時或全量同步都用同鍵去重，來源平台為 unknown。
- 手動每次產生獨立 ID；同名、同時間的多次手動紀錄全部保留。
- Takeout 使用影片 ID＋原始時間的穩定事件鍵；檔名、JSON 排版、匯入順序及批次不影響事件識別。批次使用檔案內容 SHA-256。
- 刪除外部事件後保留其外部鍵，重掃／重匯不回流；備份也保留忽略鍵。
- 不根據跨來源的接近時間自動合併。時間軸另列同首歌兩分鐘內、不同平台或方式的候選，最多 100 組，由使用者保留或刪除。這不是完整的重複鑑識。
- 歌曲版本預設保留；明確合併會二次確認歌名／歌手／版本。保留歌曲的資料與目標作為結果，全部事件只改歸屬，保留來源、時間、外部鍵與原同步歌曲鍵別名，後續同步不重新拆歌。
- 自訂平台採封存替代破壞性刪除，可恢復、改名；歷史紀錄與統計永遠保留。

## Takeout 研究與限制

參考 Google 官方 [Takeout 欄位文件](https://github.com/google/takeout/blob/main/README.md) 與 [匯出說明](https://support.google.com/accounts/answer/3024190?hl=zh-Hant)。官方欄位說明指出 title 表示活動、subtitles 是頻道資訊、details 可能標示廣告；不能把頻道直接當作可靠歌手，也沒有可靠有效播放時長。

本版使用上述欄位結構的合成測試資料，未取得使用者真實 Takeout 檔案。支援 JSON 陣列中的 HTTPS YouTube watch 網址、11 字元影片 ID、明確的觀看前綴與含時區 ISO 時間。目前辨識英文 `Watched`、繁中 `已觀看`／`觀看了`、韓文 `시청한 동영상`；其他語系安全略過。JSON 上限 50 MB、200,000 筆。廣告、搜尋、無效／無時區時間及未知事件不自動計入。

所有候選預設未確認。只在唯一的歌名＋歌手提示＋原版匹配時預填歌曲，仍須核對版本並逐筆勾選確實是 YouTube Music 聆聽，最後確認整批才寫入。無法確認可略過，或先新增正確歌曲再重選檔案。一般 YouTube 網址不視為 Music 來源證據。觀看事件並不等於官方有效串流；不推定聆聽完成度。

HTML 日期受語系／時區格式影響，本版明確拒絕並要求改匯出 JSON。沒有 HTML 成功匯入的宣稱。未知格式保留原資料，不會虛構成功。檔案解析不發出網路請求；不下載遠端曲目資料、不上傳私人紀錄。

## 未提供的自動同步

Melon 僅提供歌曲輸入、手動選平台、日期及批次次數；沒有爬蟲、私人 API 或密碼收集。YouTube Music 僅提供本機檔案預覽及使用者確認後匯入，沒有 Google OAuth、背景自動同步或即時播放追蹤。Spotify 也僅有手動平台分類；Last.fm 無可靠原平台資訊時仍顯示來源未確認。

## Android Chrome 驗收

請在測試網址或 PR 預覽操作，先下載原本網站的 JSON 備份；不同網址／網域的 IndexedDB 不共用，不要因此誤判資料遺失。

1. 用最新版 Android Chrome 開啟，同一網站只留一個分頁。舊資料的歌曲、目標與總次數應相同，舊平台顯示來源未確認；重新整理後不重複增加。
2. 首頁可取消「只看 PLAVE」。切換今日／本週／本月／累積及平台，檢查次數與占比；切換篩選後重新整理，事件總數不變。
3. 新增一首歌，選 Spotify 按 +1，再選 Melon 按 +1。展開平台明細，各有 1 次、跨平台共 2 次。
4. 按「指定日期／批次新增」，選 Melon、日期、3 次。取消確認應不新增；確認後新增 3 筆。到時間軸刪除一筆，重新整理核對。
5. 「連接與備份」新增 Apple Music，改名 Stationhead。空白／重複名稱應被拒絕。封存後歷史次數保留，恢復後可繼續計數。
6. 新增原版及 Live 歌曲，確認不自動合併。先備份，再到歌曲合併選擇兩首並核對確認；合併後總筆數、平台及時間不變。
7. 在 Google Takeout 將 YouTube 歷史格式選 JSON，下載解壓縮後到匯入頁選檔。檢查待確認、失敗、重複與略過數字；未勾選前確認按鈕不可用。選正確歌曲、勾選確認、再確認整批後核對結果。
8. 重選同檔，已匯入項目應顯示重複，總數不增加。損壞 JSON／HTML 應顯示明確錯誤，原資料不變。
9. 下載 v2 JSON，還原預覽檢查歌曲／事件數，先備份再確認補入缺少資料。平台與來源應保留；相同備份再還原不累加。
10. 在疑似重複檢視核對來源與時間，僅在確定誤記時刪除。用原 Last.fm 帳號連續增量同步兩次，沒有新 Scrobble 時次數不變（真實服務驗證需要部署已設定伺服器 API key）。

自動化手機驗證使用桌面 Chromium 的 Android 裝置／視窗模擬，不等同實體 Android 真機驗證。

升級顯示 0 的診斷與修復請見 [ZERO_DATA_DIAGNOSIS.md](ZERO_DATA_DIAGNOSIS.md)。

Android Chrome 啟動鎖定修復見 [STORAGE_LOCK_DIAGNOSIS.md](STORAGE_LOCK_DIAGNOSIS.md)。
