# 單筆聆聽紀錄管理

## 功能與資料安全

從最新 main 建立 feat/single-play-management。歌曲卡片新增「查看聆聽紀錄」，導向單筆管理。清單包含歌名、歌手／版本、平台、聆聽時間、來源與完整紀錄 ID，不受首頁期間／平台篩選影響。同歌同時間的手動紀錄仍以獨立 ID 辨識。

每筆有獨立刪除按鈕。確認視窗再次列出上述資訊；取消不寫入。確認後只將該 ID 從 plays 移到 deletedPlays，不改歌曲、目標、其他事件或同步進度。沒有自動挑選 WAY 4 LUV 測試事件、批次刪除、永久清除或自動到期。

已刪除紀錄不計入歌曲累積、平台統計與時間軸。可以切換「已刪除紀錄」核對後恢復，恢復保留原 ID、來源、平台、時間、建立時間與外部識別鍵。資料先成功寫入 IndexedDB 才更新畫面；保留原有短時間 Web Locks 與過期快照比對。

Last.fm／匯入事件刪除後保留 ignoredKeys，避免增量同步、全量重掃或同檔重匯自動補回。人工恢復時移除該事件忽略鍵，重新放回原 ID；後續同步以原外部鍵去重，仍不增加第二筆。手動紀錄不按歌名／相近時間合併或刪除。

既有時間軸與疑似重複檢視也改用相同可恢復的單筆刪除，並在確認訊息顯示完整事件資料。原有歌曲管理的整首刪除功能不是此單筆流程的一部分，不會由新入口呼叫。

## 備份相容性

IndexedDB 名稱、版本、store、key 均不變，不清空或重建。schemaVersion 仍為 2，新增可選 deletedPlays 陣列；既有 v1／v2 缺少此欄位完全正常，不需要預先寫入空陣列。

每個副本包含原 Play、刪除當時 Song 快照及 deletedAt。驗證副本的 ID、來源、時間、平台、歌曲關聯、外部鍵，拒絕與活躍事件重複或格式損壞的備份。新版下載包含副本與忽略鍵，可在另一個空白測試帳本恢復。讀取備份先複製與驗證，不修改使用者原 JSON 檔案。

安全補入舊備份不會自動復活已刪除的手動或外部事件；使用者應到已刪除清單明確恢復。含刪除副本的備份不會刪掉目前活躍事件。ID／內容衝突整批停止，不部分覆蓋；還原預覽會列出副本筆數，副本不增加聆聽數。

## 限制與風險

- 刪除屬於可恢復移除，副本仍儲存在本機與新版備份，不是隱私資料的永久抹除；請妥善保存備份。
- 僅能恢復使用此版本單筆刪除時保存的副本；更早版本已刪除但未保存的紀錄，不能憑忽略鍵虛構重建。
- 若之後另行刪除或合併原歌曲，副本與原歌曲快照仍保留，但恢復按鈕會停止／停用，不猜測另一首歌曲歸屬；需保留備份後個別核對。
- 請保留原始備份，使用支援此欄位的新版頁面管理。舊版程式可能忽略 deletedPlays，不能把新備份交由舊版另存後當作完整恢復來源。同一網址的其他頁面也應更新至新版。
- 副本沒有自動清除期限，佔用容量會增加；容量錯誤會停止寫入，不清資料。選錯仍可恢復，使用者需自行核對四筆測試事件，系統不按名稱或日期自動認定。

## Android Chrome 驗收

正式網站仍應是 21 首／58 筆；此 PR 不合併或部署正式網站，也沒有代使用者刪除四筆紀錄。請先下載目前原始備份，再於 PR 預覽使用「安全補入」測試，預覽與正式網址不共用資料。

1. 首頁找到 WAY 4 LUV，按「查看聆聽紀錄」。核對每筆平台、時間、來源及 ID；不要把原始聆聽誤認為測試紀錄。
2. 選一筆測試紀錄按刪除，確認視窗應清楚顯示該筆完整 ID。先按取消，筆數必須不變。
3. 重新選取並確認，只減少一筆，歌曲仍存在。依序核對並刪除其餘三筆；應為 21 首／54 筆，其餘歌曲與紀錄不變。
4. 到已刪除清單查看四筆副本。可恢復其中一筆，應回到 55 筆；再刪該筆可回到 54。每次都需要確認。
5. 重新整理確認副本仍在。下載新版 JSON，安全補入另一個空白測試瀏覽器時應保留副本；原備份檔不可被修改。
6. 若刪的是 Last.fm 事件，連續同步不應補回；明確恢復後再次同步，仍只有原本一筆。真實 API 驗證需要現有伺服器環境，開發自動化使用模擬回應。

## 測試範圍

合成 21 首／58 筆案例，逐筆選四個 ID 移除，對剩下 54 筆逐欄深度比對，且歌曲、目標、watermarks、游標不變。涵蓋同時間手動事件、取消、ID 不存在、持久恢復、Last.fm 重掃與恢復去重、新舊備份、副本格式與衝突拒絕、安全補入不復活／不刪現有事件、原歌曲不存在安全停止，以及歌曲與平台統計更新。

沒有使用或上傳私人播放紀錄，沒有在正式網站寫入測試資料。手機驗證為 Chromium 360px／393px 模擬，不宣稱實體 Android 已測試。
